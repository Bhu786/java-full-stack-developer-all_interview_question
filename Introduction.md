Coming to my current project, I am working on a banking-domain project, specifically in the Credit Servicing layer. Our application handles various credit-card-related operations. It determines customer eligibility for credit cards and supports operations such as credit-card transactions, bill generation, statement generation, due-date reminders, and customer notifications.

Our project follows the Agile methodology, and I am involved in the complete end-to-end development lifecycle.

I participate in backlog grooming and sprint-planning meetings to understand and prioritize the requirements. Once a story is assigned to me, I receive the functional design document from the functional team, which is located at the client side. I go through the document and understand the business requirements. If I have any questions or need clarification, I discuss them with the functional team before starting the implementation.

Once the requirements are clear, I work on the technical design, including designing the required database tables and determining the application-level changes. After the design is finalized, I start the development. I am responsible for both backend and frontend development as part of my role.

After completing the development, I perform unit testing to make sure the functionality works as expected. I also perform code reviews to identify and fix any coding issues before integrating my changes with the rest of the team's code in Git.

Once the code is integrated, I work with the DevOps team for the CI/CD pipeline and use Jenkins to automate the build and deployment process. I execute the pipeline and deploy the application to the development or integrated environment, where I perform initial validation and resolve any issues found.

After my development is completed, I hand over the functionality to the QA team. The QA team performs functional testing and reports any defects. I analyze the defects, fix valid issues, and provide the updated build for testing.

Our project also goes through User Acceptance Testing at the client location. During UAT, if any issues are identified, I analyze whether they are valid, fix the issues when required, and provide the updated code to the UAT team.

Apart from development activities, I also participate in production release activities and production-support calls. If any production issues occur, I analyze the root cause and work on fixing them.

So overall, I am involved in the complete software development lifecycle, starting from requirement understanding and technical design to development, testing, CI/CD deployment, UAT, production release, and production support

# Roles & Responsibilities – Java Full Stack Developer

## 🎯 Interview Question

> **Interviewer:** What are your roles and responsibilities in your current project?

### 💬 Interview Answer

As a **Java Full Stack Developer**, my responsibilities cover the complete software development lifecycle, starting from requirement understanding and development to testing, deployment, and production support.

---

## 1. 📋 Understand Requirements & Query Log

* First, I understand the **business requirements** provided by the functional team.
* The functional team collects requirements from the client and provides the requirement document to the development and testing teams.
* I go through the requirements carefully and identify any:

  * Doubts
  * Ambiguities
  * Missing information
  * Business-related questions
* I document these questions in a **Query Log**.
* I discuss the Query Log with the functional team and get the required clarifications before starting development.

**Interview line:**

> "My first responsibility is to understand the business requirements clearly and clarify any open questions with the functional team before starting development."

---

## 2. 🔀 Repository & Pipeline Request

Once the requirements are clear:

* We need a source-code repository such as **GitHub/Bitbucket**.
* Since multiple developers work on the same project, all source code needs to be maintained in a common repository.
* We raise a **Jira request to the DevOps team** for:

  * Git repository creation
  * Jenkins pipeline creation
* The DevOps team provides the repository and pipeline details.
* Jenkins is used to automate the **build and deployment process**.

**Interview line:**

> "We coordinate with the DevOps team through Jira for repository and Jenkins pipeline setup required for development and deployment."

---

## 3. 🗄️ Database Design

Before development, I understand the database requirements.

My responsibilities include:

* Identifying required tables
* Identifying columns
* Defining relationships between tables
* Understanding data flow
* Maintaining proper relationships and normalization

**Interview line:**

> "Based on the business requirement, I work on the required database design, including tables, columns, relationships, and normalization."

---

## 4. 💻 Development & Unit Testing

After the database design:

* I start implementing the application functionality.
* I develop the required **business logic**.
* I write the required application code.
* Once development is completed, I perform **unit testing**.
* I verify that the code works as expected before sharing it with the testing team.

**Interview line:**

> "My core responsibility is implementing the required business logic and then performing unit testing to make sure my code behaves as expected."

---

## 5. 🔍 Code Review

After unit testing:

* The code goes through **code review**.
* We check:

  * Coding standards
  * Naming conventions
  * Best practices
  * Possible bugs
  * Code quality
* If any issues are identified, I make the required changes.

**Interview line:**

> "After development and unit testing, I participate in code reviews to ensure code quality, coding standards, and best practices are followed."

---

## 6. 🔀 Code Integration

After the code review:

* I commit my code to the **Git repository**.
* Multiple developers may be working on different features simultaneously.
* Therefore, I need to make sure:

  * My changes don't conflict with other developers' changes.
  * The correct branch is used.
  * Merge conflicts are resolved properly.
  * Other developers' code is not negatively affected.

**Interview line:**

> "After code review, I integrate my changes into the Git repository while making sure there are no conflicts with other developers' work."

---

## 7. 🧪 DIT – Developer Integration Testing

After code integration:

* The integrated application is deployed to the **DEV environment**.
* Jenkins is used for the deployment process.
* I perform **Developer Integration Testing (DIT)**.
* The objective is to verify that:

  * My code works after integration.
  * Existing functionality is not broken.
  * Different components work correctly together.
* If I find any issues, I troubleshoot and fix them.

**Interview line:**

> "After integration, I deploy the application to the DEV environment and perform DIT to verify that the integrated application is working correctly."

---

## 8. 🧪 SIT – System Integration Testing

After DIT is completed:

* The application is promoted to the **SIT environment**.
* The **QA/testing team** performs System Integration Testing.
* QA may identify defects.
* Defects are reported using **Jira**.
* I analyze the reported issue.
* I fix the defect and provide the updated code/build.
* Once all issues are resolved, the QA team provides the required **SIT approval/certification**.

**Interview line:**

> "After DIT, the application moves to SIT where the QA team validates the system. If defects are reported through Jira, I analyze and fix them."

---

## 9. 👥 UAT – User Acceptance Testing

After SIT approval:

* The application is promoted to **UAT**.
* UAT is performed by the:

  * Client
  * Client-side team
  * Business users
* They verify whether the application meets their business expectations.
* If issues are identified:

  * I analyze the issue.
  * Fix the problem.
  * Provide the updated code/build.
  * Support the UAT team.

**Interview line:**

> "After SIT approval, the application moves to UAT where the client or business team validates the application from a business perspective."

---

## 10. 🚀 Production Support & Log Monitoring

After UAT and the required pre-production activities:

* The application is deployed to **Production**.
* Production is the environment accessed by actual end users.
* If a production issue occurs, it becomes a high-priority issue.
* My responsibility is to:

  * Analyze the issue
  * Check application logs
  * Identify the root cause
  * Troubleshoot the problem
  * Fix the issue
  * Support the deployment of the fix

### 🔎 Log Monitoring

For troubleshooting, I need to understand application logs and use log-monitoring tools such as:

* **ELK**
* **Splunk**

**Interview line:**

> "I also provide production support. If a production issue occurs, I analyze the application logs, identify the root cause, fix the issue, and support the required deployment."

---

## 11. 📚 Documentation & Knowledge Transfer

Apart from development and support:

### Documentation

I contribute to project documentation such as:

* Application architecture
* Project modules
* Module responsibilities
* Application execution flow
* Database design
* Project development information

### Knowledge Transfer (KT)

When a new developer joins the team, I explain:

* Project architecture
* Application modules
* Database
* Application flow
* Development process
* Important project information

**Interview line:**

> "I also contribute to technical documentation and provide KT to new team members so they can understand the project architecture, modules, database, and application flow."

---

## 12. 🔬 POCs, In-House Training & Management Feedback

Another responsibility is technical research and improvement.

### POC – Proof of Concept

When a new:

* Framework
* API
* Technology
* Technical approach

is required, I can perform a **POC** to verify whether it works as expected and whether it can be useful for the project.

### In-House Training

If I learn something useful for the project:

* I can share it with team members.
* I can conduct internal/in-house knowledge-sharing sessions.

### Management Feedback

I also communicate with management to:

* Understand how I am contributing to the project.
* Take feedback on my work.
* Identify areas for improvement.
* Understand expectations for the next level.

**Interview line:**

> "I also contribute to POCs and knowledge-sharing sessions, and I take regular feedback from management to improve my technical contribution."
