In the second step: we need to explain what are our technical skills, what technologies we have used in our past experience. **Roles & Responsibilities Detailed Breakdown** [[06:22](https://www.youtube.com/watch?v=PvYAhRIp1-Q&t=382)]

> "In this video, we will understand what are the roles and responsibilities of developers in software job, and this is very important interview question also. All right, let's get started.
> 1. **Understand Requirements & Query Log:** As a developer, the first thing is we need to understand requirements. We will get the requirements from functional team. Between the development team and a client, functional team will be available. Functional team is responsible to understand the client business and will collect requirements from the client, will prepare requirements document. They will share the requirements document with development team and testing team. As a developer, we need to understand all the requirements given in that document. When we are trying to understand that requirement document, sometimes we will get some confusions and we will get some doubts also. For that, we are going to prepare query log document. Query log is used to write down all the doubts that we have on the requirement. Functional team is responsible to provide clarifications on those doubts. So we need to set up meeting with functional team and we need to discuss our doubts on the requirement. [[06:38](https://www.youtube.com/watch?v=PvYAhRIp1-Q&t=398)]
> 2. **Repository & Pipeline Request:** Once functional team clarified all those doubts, then we need to start our actual work on the project. Here we need to raise a request for DevOps team to create a Git repository or Bitbucket repository. In the team, multiple developers will be available, so we need a repository to integrate all the developers' code at one place. We will raise a Jira request to the DevOps team to create that repository. DevOps team will create that repository and will share the repository details with development team. Along with the repository, we need a Jenkins pipeline to automate build and deployment process of our project. For that also we need to raise a request for DevOps team using Jira ticket. So DevOps team is responsible to create GitHub repository and Jenkins pipeline. [[07:43](https://www.youtube.com/watch?v=PvYAhRIp1-Q&t=463)]
> 3. **Database Design:** Once those things are completed, then we need to understand database tables required for our project. So as a developer, we need to perform database table design: how many tables we need for our requirement, what are the columns we need, what are the relationships we need to establish to normalize the data—that we need to perform. [[08:38](https://www.youtube.com/watch?v=PvYAhRIp1-Q&t=518)]
> 4. **Development & Unit Testing:** After database design is completed, then we will start our actual development. We need to write the business logic which is required for our project based on the given requirement. We need to implement our logic. Once development part is completed, then we need to perform unit testing. Whatever the code we have written directly we cannot give to the client, right? Whatever the code we have written, is that code working as expected or not—we need to test it. That is called unit testing. Yes, as a developer you are responsible to develop as well as test the code also. [[08:52](https://www.youtube.com/watch?v=PvYAhRIp1-Q&t=532)]
> 5. **Code Review:** Once your code testing is completed, once you are confident that every line of code is working as expected, then we are going to perform code review. There are several code review tools available in the market. By using them we can review our code, we can correct our mistakes also by using that code review. Every team member, every developer will store the code into GitHub repository. And we need to make sure that our code when we are storing into the repository, there should not be any conflict. Our code should not disturb the other developers' code available in the repository. We should be very careful while integrating the code into repository because the project source code is everything—without source code there is no project. We should be very careful when we are integrating the code into repository. Remember that other developers' code should not be affected when we are merging our code into repository. [[10:06](https://www.youtube.com/watch?v=PvYAhRIp1-Q&t=606)]

When I have done that coding it worked as expected in my system; is that code working as expected after integration? Again we need to test it. That's where Dev environment comes into picture. As a developer, we need to deploy our code in the Dev environment. For that, Jenkins job will be created by DevOps team. We need to send that request for the DevOps team, right? We will send the request for the DevOps team to create the Jenkins pipelines which are required for our application. So Jenkins pipeline we need to execute to run our code in the Dev environment. Once the code is deployed in the Dev environment, we need to perform integration testing: is our code working as expected or not after that code is integrated? As part of that integration testing, we may get some issues also, and as a developer we are responsible to fix those issues. That is called Developer Integration Testing—we will also call it as DIT.
